# 風哨 GALEPOST

**站臺：https://xin7355-collab.github.io/GALEPOST/**

颱風期間的**站臺設備關（待）機管制與回報產生器**。單一 HTML 檔、可離線、可安裝成 App。

抓中央氣象署的颱風路徑潛勢預報，用修正型渦旋模型逐時內插，推算每個站臺何時達到關機風級、
何時可以復機，並直接產出可以貼進通報的回報文字。

> 畫面上的風級是**推估**，不是實測。氣象署發布的警報單才是單位行動的依據——
> 程式把兩者分開顯示，就是為了不讓人把推估當成官方數字。

## 快速開始

不需要任何建置流程，`index.html` 自己就是完整的程式：

```bash
# 任一靜態伺服器皆可（Service Worker 需要 http，直接開檔案不會有離線功能）
npx http-server -p 8080 .
# 瀏覽器開 http://127.0.0.1:8080/index.html
```

第一次進來沒有任何站臺資料——本程式不內建任何單位或站臺，
請按「新增站臺」，或把過去的回報文字整段貼上自動建檔。

站臺清單與回報稿**預設依地點由北至南**（座標緯度遞減，沒填座標的排在最後）。
要改成自己的順序，到站臺頁的「排序」選「自訂順序」，卡片右側會出現上下箭頭。
設定頁的站臺清單另有自己的排序（由北至南／名稱／類別／自訂），跟站臺頁分開——
站臺頁是用來掃狀態的，設定頁的清單是用來找到某一站去改它。

設備類別除了名稱與回報用語，還有兩個開關：

- **地形**——停班停課的 24 小時雨量基準（平地 350 mm／山區 200 mm）。
  預設的雷達與紅外線類別都是平地；「中繼站臺」是山區。個別站臺可在該站「編輯」裡覆寫。
- **列入回報稿**——關掉的類別（預設是「中繼站臺」）不會進交接通報，
  但仍出現在站臺頁、衝擊預判與播報。站臺卡上會標「不列入回報」。

## 颱風資料的三條路徑

程式依序嘗試，前面的取得了就不會往下走：

| 順序 | 來源 | 需要金鑰？ | 有預報路徑？ |
|---|---|---|---|
| ① | `data/typhoon.json`（後端事先抓好） | 使用者端不必 | 有 |
| ② | 使用者自填授權碼直連中央氣象署 `W-C0034-005` | 要 | 有 |
| ③ | GDACS 全球來源 | 不必 | **沒有**，只有觀測位置 |

目前 repo 還沒設定 `CWA_API_KEY` Secret，所以 `data/typhoon.json` 是 `hasKey:false` 的空殼，
前端會自動略過它、退到第②或第③條。到 repo → Settings → Secrets → Actions
新增 `CWA_API_KEY`，並補上後端抓取管線之後，使用者端就再也不必自己申請授權碼。

瀏覽器直連氣象署常被 CORS 擋。設定頁可以填一個代理網址（Cloudflare Worker 之類，
格式為 `POST {cwaDataset, cwaKey, cwaParams}`），直連失敗會自動改走代理；
兩條都失敗時，畫面上會寫出**真正的原因**，而不是默默退到 GDACS
讓人誤以為「氣象署就是沒發布」。

## 停班停課

颱風頁的**停班課**子頁籤把兩件事合成一張表：**官方公告**（事實）與**本機推估**（推算），
一個縣市一列，**全臺 22 個縣市**分三組：
**西部（由北至南）→ 東部（宜、花、東）→ 外離島（澎、金、馬）**，兩者都標明是哪一種。
純照緯度排會把連江擺最前面、金門插在苗栗與臺中之間——緯度上沒錯，
但看的人是照著本島從上往下找自己的縣市，離島夾在中間會讓那條線斷掉。

官方那一頁取自
[人事行政總處](https://www.dgpa.gov.tw/typh/daily/nds.html)。
它沒有 CORS 標頭，瀏覽器直連一定被擋，所以要透過代理取 HTML 再自己解析
（做法取自使用者提供的 betterdgpa）。縣市分三種狀態：
**全縣停（紅）／部分地區停（琥珀）／照常（綠）**——官方那張表在高雄市、屏東縣這種情況下
整格裡一條全縣的敘述都沒有，只有逐區逐鄉的十幾行；把整個縣市塗紅等於說全市放假，那並不成立。
細部地點收在折疊裡（標題會寫「12 個地區停止上班上課」），不展開也知道規模。
**公告一律不進離線快取**——昨天的公告寫著「明天停止上班」，今天讀到那一行會直接讀成今天放假。

代理網址在設定「停班停課來源」可以改成自己的，或清空只看官方連結；也接自訂的 JSON 端點。

推估依《天然災害停止上班及上課作業辦法》兩款：

- **風力**——平均風 7 級以上或陣風 10 級以上，由預報路徑逐時推算**各縣市政府所在地**
  （陣風以持續風 1.3 倍估算）。山區與離島的實際風雨會與代表點不同。
- **雨量**——第四條附表逐縣市認定（多數縣市平地 350、山區縣市山區 200、連江縣 200 毫米；
  南投平地 300、宜蘭 250、連江 180 另訂**實際觀測**基準）。附表的值是「未來 24 小時累積雨量
  **預測**」，本程式沒有預測雨量，改用氣象署的**豪大雨特報**當替代訊號——特報本身就是預測性質，
  門檻同一個口徑。這仍是替代訊號不是官方數字：特報是分級，不是逐點預測值。

表上還會寫**推估何時前後解除**（風力款取最後一段達標時段的結束、雨量款取特報有效期）。

> 推估不是公告，一律以官方為準。達到基準也不必然放假：辦法還要求「已致災或有致災之虞」，
> 而且宣布權在地方政府綜合研判。

**實測**的 24 小時累積只有南投平地、宜蘭、連江那三個縣拿來比才是官方依據；
其餘縣市拿實測去比只是參考，站臺卡上會分開標示。

## 颱風頁的八個分頁

**概況／播報／警報／天氣／停班課／路徑／實況／站臺**，在手機上排成 4+4 兩排
（一排塞不下時橫向捲動會把後面幾格藏起來，值班的人不會知道那裡還有東西）。

- **警報**——官方警報單（事實）在上，本機推算的發布時機在下。兩者風險完全不同，不混成一張卡。
- **天氣**——現在有沒有在下雨（實測）＋ 逐 3 小時到第 3 天（預報）。

取名為「天氣」而不是「氣象」：同一列裡「警報」本身也是氣象，兩格都用氣象類的名字會分不出來。

概況頁是那張颱風卡加**三行摘要**（警報／天氣／停班課），每行是那一頁的一句話版本，按下去跳過去。

## 天氣（是否下雨、未來三天）

分成**實測**與**預報**兩件事，畫面上刻意分開講——值班回報時「現在」跟「等一下」的責任不一樣。

| 要回答的 | 用什麼 | 解析度 |
|---|---|---|
| **現在**有沒有在下雨 | 自動氣象站的 10 分鐘累積雨量 | 實測、10 分鐘 |
| 未來 0–3 小時 | 雷達回波（實況頁圖層） | 影像 |
| 未來 2 天 | 鄉鎮天氣預報 `F-D0047-089` | **3 小時一格** |
| 第 3 天以後 | 鄉鎮天氣預報 `F-D0047-091` | 12 小時一格 |

> **沒有逐 1 小時的降雨預報。** 氣象署開放資料裡最細就是 3 小時，本程式**不做內插**。
> 把 3 小時的「天氣現象」硬切成 1 小時，內插不出中間那一小時是「陰」還是「陣雨」——
> 那是把猜的講得比較細。要看「等一下會不會下」，該看的是雷達回波，不是預報表。

兩支資料集是**接續**的：同一個鄉鎮的同一個欄位，保留細的那一份，
再把時間在它之後才開始的粗格接到尾巴，所以第 3 天以後才有東西。
站臺對鄉鎮優先用**座標**找最近的，沒有座標才退回縣市名稱比對，再不行就不猜。

資料集代號可在 **設定 →「天氣預報來源」** 修改，留空就不抓那一支；
抓不到時卡片會直接寫**是哪一支代號失敗**，不會靜靜空白。

## 「無停班停課訊息」不是取得失敗

沒有颱風的日子，人事行政總處那張表裡**一列縣市都沒有**，只有一格「無停班停課訊息。」。
那是**官方今天已經給出的答案**，不是解析失敗——程式會認出來，那一天每個縣市顯示
**照常上班上課**，而不是「尚未取得」。後者會讓人以為公告還沒出來，其實已經出來了，寫的是沒事。

表格在、但既沒有縣市也沒有那句話（例如整頁換成「系統維護中」），仍然照常報「找不到縣市資料」。

## 地形與風力校正

模型算的是**海面上的持續風**，沒有地形。真正的地形修正要有高程資料與地形追隨的
邊界層模式，不是單檔前端程式的量級——硬做只會做出一個看起來很準的假數字。

做得到的是另一件事：**拿這個站自己的實測去學它的偏差**。每次更新時，同一個地點同時有
模型推估與最近測站實測，比值就是這個站的曝風／地形修正係數，累積起來之後乘回推估上。

- **依風向分八個方位各學一組**——同一個站吹北風被山擋住、吹南風整片敞開，係數可以差一倍。
- 只在推估 ≥ 5 m/s、測站在 **25 km 內**時學（顯示用 60 km，學習要更嚴），係數夾在 0.35–1.8。
- 樣本不足（< 3 筆）就不套用，**寧可不校正也不亂校正**。
- 校正同時套用到**關機與復機時間**，不只是畫面上那個級數。
- 站臺卡標「地形校正 ×1.15」；編輯頁看得到樣本數、各方位係數、取自哪個測站，
  可以手動覆寫、停用或清除重學。

> 修得掉的是曝風、遮蔽、測站高度這類**系統性偏差**；修不掉的是路徑誤差造成的時間偏移，
> 以及複雜地形裡的瞬間陣風。所以畫面上仍然並列實測，也保留「推估差 N 級」的警告。

## 地圖上的站臺

**顏色講狀態**（開機綠／待機琥珀／關機紅／未建置虛線灰），
**符號講類別**（雷達 ◎、紅外線 🔺、中繼 📡，可在設備類別裡改成任何字或 emoji）。
每個類別自成一個圖層，右上角可逐類開關。地圖上方有「全域／對焦站臺」——
颱風還在一千多公里外時，全域框出來自己的站臺只是海岸線上的一小撮。
右下角的 ⛶ 進全螢幕（Esc 或再按一次離開），切換後會自動重新框選。

## 幾個介面上的約定

- **戰力 N / M**：M 只算「已建置且會進交接通報」的站。未建置與自用監看的類別
  （預設是「中繼站臺」）都不計入，也不在站臺管制的預設清單裡——
  要看它們得按「未建置」或該類別的「＊」篩選鈕。
- **顏色只給目前狀態**：站臺卡上三顆狀態鈕，只有「現在是哪一個」會填色；
  上方三格統計數字為 0 就壓暗（紅色的「0」看起來像警報，其實是「一臺都沒關」）。
- **自用監看**用自己的紫色並整張框起來——它不在交接名冊上，跟開機／待機／關機
  是兩件事，不該共用那三個顏色。
- **兩指撐開可以暫時放大**任何頁面（地圖除外，那裡有自己的縮放），放開就彈回。
  要一直維持大字請用設定**最上面**的字級。
- **自用監看是獨立開關**，不跟類別篩選同步——它問的不是「只看這一類」，
  而是「要不要把不列入交接的也放進來」。
- **日期一律帶星期**（`8月24日(一)`、`8/24(一) 22:00`），回報稿也帶。
  值班表是按星期排的，看到「8月27日」還要自己想那是週幾，正是排班最容易算錯的一步。

## 本次管制

設備平常本來就是開機，那是**常態不是動作**——所以「狀態變更時序」在還沒開始管制時
是空的，不會憑空生出一排「完成開機」。按站臺頁的**「開始管制」**之後，
每一次開機／待機／關機才會記進本次時序與回報（回報的「已復機起算時間」會一起推到那一刻）。

## 備份

設定 →「資料與安全」可以選**匯出範圍**：

| 範圍 | 內容 | 匯入時 |
|---|---|---|
| **全部（完整備份）** | 站臺、類別、設定、紀錄、本次管制、**授權碼**、來源網址，加上字級／底圖／對焦等顯示偏好 | 問你要**取代**還是**合併** |
| **單一設備類別** | 只有那個類別的站臺、它的類別定義與相關紀錄。**不含設定與授權碼** | **一律合併**，其他類別不動 |
| **僅設定** | 門檻、用語、授權碼、來源網址、類別定義。**不含任何站臺** | 只動設定，不碰站臺 |

檔名帶上範圍（`風哨備份_岸際雷達_….json`），要還原時分得出哪個是哪個。

匯入的檔案選擇**刻意不設 `accept`**——Android 的檔案選擇器是照 **MIME** 過濾的，
不是照副檔名，而下載下來的備份常被記成 `application/octet-stream`，
一設 `accept=".json"` 那些檔案就變灰的、點不下去。
選擇器如果還是選不到，「資料與安全」裡有一組**完全不經過檔案系統**的路：
這一台按**「複製備份內容」**，那一台用**「貼上備份內容」**貼進去。
Android 的下載或選擇器出任何問題，這條都還走得通。

匯入失敗時會講出**實際讀到什麼**（幾個字元、開頭是什麼、是不是 HTML、
是不是 JSON 斷在中間），而不是只說「不是有效的 JSON」。

分類的備份**必須**用合併匯入——只匯出雷達、再整份套上去的話，紅外線與中繼站臺就沒了。
類別 id 在兩台裝置上不一定一樣，所以分類備份帶著自己的類別定義，匯入時照名稱對回去。

> 因為含授權碼，**備份檔等同憑證，不要外傳**；要給別人看請用「加密匯出」。
> 開啟密碼也在裡面，但匯入時會先問要不要一併還原——不問就蓋掉的話，
> 還原一份忘了密碼的舊備份會把人鎖在門外。

颱風資料不備份，每次重抓即可——備份它只會過期。舊格式的備份仍然讀得進來。

## 更新

程式本體是快取優先，裝過一次之後手機上可能一直是舊版而看不出來。
**設定頁最下方有版本號與「檢查更新」按鈕**。新版預設不會在你操作到一半時
自動抽換——颱風天尤其不該——要換版請自己按。
